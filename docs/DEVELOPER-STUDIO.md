# Concierge Code

Concierge Code is an optional Desktop tool for code in a Concierge Project. The person opens it from the Project page. On first use, Concierge downloads a pinned OpenVSCode Server release into the default WSL distribution, checks its SHA-256 digest, and starts it on the Windows loopback interface with a fresh connection token. The editor opens in a full-screen view inside Concierge. The Project's source folder stays in the person's local Concierge app data. Circle AI is the Concierge coding assistant; the embedded workbench's separate agent panel is not connected to it.

The tool is currently supported on **Windows x64 with WSL**. It is not installed or started during Concierge startup. Its server is stopped when the editor closes. A recorded Linux process ID lets the next open clean up an editor left behind by an abrupt Desktop exit. No editor port is exposed to the LAN or Internet.

The editor uses a stable loopback port when available so its web client can retain the person's theme and layout choices across restarts. If that port is occupied, it uses an available port for that session; web client preferences may not carry to that temporary origin. Concierge seeds a dark theme, hidden secondary sidebar, and no welcome page for a new settings profile, and changes the workbench's product title to Concierge Code. The upstream workbench still contains some built-in VS Code instructional wording; removing every upstream string requires maintaining a branded workbench build rather than rewriting downloaded JavaScript at runtime. Its separate agent panel is not Circle AI.

The workbench is based on the open-source OpenVSCode Server and offers compatible extensions through Open VSX. Concierge Code offers optional Python and C# setup buttons. The Python setup installs `ms-python.python`, `ms-python.debugpy`, and `charliermarsh.ruff`; the C# setup installs `muhammad-sammy.csharp` and `EditorConfig.EditorConfig`. These are fetched directly from the registry when chosen; they are not bundled with Concierge. A person can also install a VSIX they choose. Extension availability and licenses must be reviewed individually; Microsoft Marketplace access is not assumed. Server data and installed extensions live under Concierge's own `developer-studio` app-data folder, under the same app-data root as Project source. Web client appearance and layout live in WebView browser storage. A future Concierge data export must cover all three; this change does not implement that export. The downloaded runtime is not checked into this repository. OpenVSCode Server's license is MIT; preserve its notices if a future installer redistributes it.

This is the **create and edit** portion of the production path. Concierge can use Project workflows and its tools to plan and review code. Publishing to SleptON! remains separate: its current `publish` command is declared but has no handler wired to it, while the available subprocess adapters are read-only. Live release submission and final approval need a running service and an end-to-end acceptance test. Concierge Code does not publish by itself.

Acceptance evidence for the Windows pilot: an editor opened from a Concierge Project; a `README.md` edit was saved to the Project's local source folder; the extension catalogue populated; a request without the token returned HTTP 403; and closing the editor stopped the loopback listener and its Linux process. After a forced Desktop exit left the editor process running, opening the same Project again stopped that stale process and started a fresh editor. Cross-platform editor packaging and live SleptON! publishing are not verified.

On 20 November 2026, the live Desktop check exposed a CRLF startup-script failure; normalizing the script before WSL execution fixed it. Python and C# setup installed their chosen extensions and the app later reported both packs installed. Both the page and editor toolbar opened a fresh, project-linked Circle AI conversation. The editor opened the Project source in restricted mode. The seeded default appearance and workbench title still need a fresh-profile visual check.
