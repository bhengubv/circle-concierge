## Release boundaries still open

- A global API key is a host gate, not a person's sign-in. Ordinary browser navigation cannot supply the custom header. The public Web app still needs the planned phone-approved QR session and person-bound authorization on every conversation, project, artifact, and Away endpoint. `2026-11-03-auth-boundary-review.md` records the missing contract. The explicit pilot setting does not solve this; do not expose a shared Web store as a multi-person service yet.
- A Desktop/Mobile address that answers over LAN is only reachable. It is not paired. Remote mobile access needs authenticated pairing and a protected transport before private work crosses that link. The new gate deliberately rejects anonymous LAN access and keyed cleartext HTTP.
- Local SQLite content and the JSON secret store rely on OS account permissions. They are not encrypted by these changes. Device-level encryption, backups, export, and loss-of-device behavior need separate acceptance.
- The HTTP middleware tests prove their decisions, but a deployed reverse proxy, TLS termination, phone QR flow, and two-person isolation have not been tested end to end here.
- Concierge Code uses a one-time URL fragment for local launch and a scoped HttpOnly session cookie after exchange. The shared Desktop route builder and ready contract were updated for that protocol. The embedded Code workspace rendered in the Desktop debug build. Browser history, cookie handling and the creative Studio surfaces were covered by Concierge Code's own smoke tests; they were not repeated inside Desktop WebView2 here.
