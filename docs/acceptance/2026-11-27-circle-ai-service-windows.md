# Windows Circle AI Service acceptance — 27 November 2026

The web entries are `https://studio.circleos.co.za/concierge` for Concierge and
`https://studio.circleos.co.za/conciergecode` for Concierge Code. These routes
do not proxy or replace the Windows-local Circle AI Service connection.

Concierge Desktop uses `Concierge.Ai.Service/CircleAiOmniLoopbackRuntime.cs` inside its own Windows process. Its production `HttpClient` has the fixed base address `http://127.0.0.1:8088/`, disables proxies and redirects, reads `GET /status`, and sends `POST /ask`. It sends the full user/assistant conversation and the latest question as `text`; it sends no system role. Requests are serialized and have a 12-minute timeout. A 503 waits for readiness; a 500 is displayed without retry. The app never calls `/stop`, starts the service, or changes sources.

The final Windows Release build succeeded with zero errors and 12 shared-UI warnings. Its `Concierge.deps.json` contains `Concierge.Ai.Service` and contains no `CircleAI`, `MNN`, `OnnxRuntime`, `Concierge.Chat.Cloud`, `Concierge.Media.Cloud`, or `Concierge.Ai.Isolated` dependency. The output folder has no CircleAI, MNN, or ONNX DLL. Concierge Code's own Windows process uses `CircleAiServiceClient.cs` with the same fixed loopback address and no AI package reference. Its live Studio run read status and received an answer through its authenticated UI route; nine focused tests passed.

Concierge focused tests passed 49/49, including direct-client, safety, and UI contracts. The shared conversation runner now disables Concierge-side tool and skill orchestration for the service-owned AI runtime; the safety wrapper forwards that boundary and a focused test checks it. A separate raw service request returned the capital of Ethiopia, and a raw multi-turn request used the supplied city context. The rebuilt Release app showed the service as ready, showed a working state during a local question, and displayed the service's answer `4` to “What is 2 plus 2?” in the conversation.

The person then stopped the real service. A direct request to `127.0.0.1:8088/status` returned connection refused. Concierge Desktop displayed “Circle AI Service is not running”; its Library loaded saved conversations. Opening Settings exposed an unregistered Windows voice downloader and triggered the Blazor error boundary. The Desktop Settings panel now excludes that mobile-only component and the unused provider-key editor. The corrected Release build compiled with zero errors and 12 warnings; the rebuilt app opened Settings while offline, displayed the stopped-service status, and reopened on Home with clear outage guidance. Concierge Code's browser Studio showed the stopped-service state and independently exported Games (727 bytes), Video (84,922 bytes), Audio (769,788 bytes), and Images (965,993 bytes). Its authenticated output catalogue, reload, preview, download, project isolation, shutdown, and token removal passed. Concierge Code client tests passed 9/9.

The person restarted the real service. `GET /status` first reported `engine=starting`, then `service=up, engine=up`. Concierge Code's live Studio route then returned a real Circle AI answer to the Ethiopia question; its four creative exports and isolation checks passed again. The Concierge Desktop client has a background ten-second status poll, and a new focused test exercises connection refused → ready → answer (all nine service-client tests pass). The existing Desktop process stayed running, but Windows UI automation could no longer read its window after the restart, even when the person brought it forward. A live post-restart Desktop UI answer is **unverified**; the previous live answer before the outage passed.

The shared safety contract keeps the same audit JSON property names and enum values as the former CircleAI content-policy types. The Android app compiled after moving service-link helpers into the Android-facing AI assembly. APK packaging failed with `XABAA7000: No space left on device`; the failed generated Android `obj` and `bin` directories were removed, leaving approximately 2.5 GB free. An Android APK is not verified by this run.

The full Concierge test assembly was rerun after updating three UI test contracts for the service-owned Windows path: 2,768 passed, two failed, none skipped. They expect a 4B selection and a nonempty progressive model list, but this machine now has only 2,377,281,536 bytes free on C:; the test's temporary model directory is on that drive and its selection is sensitive to the live device probe. The low storage is a plausible cause, not a verified root cause. These tests do not exercise the Windows service client and remain red. A media preview test failed in the first full run and passed in the second; its intermittent behavior remains uninvestigated.
