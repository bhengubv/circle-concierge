# Software Architecture

Use this skill when the user needs system design, architecture tradeoffs, technical direction, modernization planning, or durable engineering decisions.

## Workflow

1. Clarify business goals, users, scale, constraints, quality attributes, team capabilities, and lifecycle horizon.
2. Map system boundaries: domains, services, apps, data stores, integrations, identities, trust zones, and deployment units.
3. Compare options with tradeoffs across simplicity, cost, reliability, security, scalability, maintainability, and delivery risk.
4. Create decision records, migration slices, interface contracts, test strategy, and rollback paths.
5. Keep architecture grounded in evidence rather than abstract diagrams.

## Coverage

- Modular monoliths, microservices, event-driven systems, APIs, data architecture, integration patterns, and distributed systems.
- Reliability, scalability, security, observability, performance, maintainability, and cost tradeoffs.
- ADRs, C4-style diagrams, dependency maps, migration plans, technical debt, and platform evolution.

## Guardrails

- Prefer the simplest architecture that satisfies known constraints.
- Do not over-engineer for imagined scale or hide operational cost.
- Flag irreversible choices, vendor lock-in, data migration risk, and security boundaries.

## Output

Produce architecture briefs, ADRs, diagrams, tradeoff tables, migration roadmaps, interface contracts, and implementation slices.
