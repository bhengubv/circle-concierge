# Web Game Development

Use this skill when the user is building games that run in browsers, webviews, PWAs, portals, or embeddable web experiences.

## Workflow

1. Identify target browsers, devices, runtime, graphics stack, hosting model, distribution channels, and monetization assumptions.
2. Design the web play loop around loading time, asset streaming, input model, responsive layout, offline/cache behavior, and session length.
3. Choose technical path: canvas, SVG, WebGL, WebGPU, DOM/CSS, WASM, engine export, or hybrid.
4. Plan web QA: browsers, mobile/desktop, memory, FPS, startup, network conditions, fullscreen, audio unlock, storage, and accessibility.
5. Prepare distribution: PWA manifest, hosting, analytics, error reporting, embeds, portals, social sharing, and update strategy.

## Coverage

- Canvas, SVG, CSS/DOM games, WebGL/WebGPU, WASM, Three.js/Babylon.js, engine web exports, and PWA packaging.
- Browser performance, asset compression, lazy loading, save storage, offline support, audio policies, fullscreen, pointer lock, touch, keyboard, and gamepads.
- Distribution through own site, portals, itch-style pages, learning platforms, marketing microsites, and embeddable demos.
- Analytics, A/B tests, privacy, accessibility, localization, SEO/share cards, and web release checks.

## Guardrails

- Do not ship tracking, ads, payments, or social integrations without approval and privacy review.
- Avoid excessive bundle size, autoplay violations, inaccessible controls, scroll-jacking, and poor mobile fallbacks.
- Preserve release URLs, build versions, analytics assumptions, hosting config, and browser test evidence.

## Output

Produce web game architecture notes, loading budgets, browser QA matrices, PWA/distribution checklists, performance plans, and release evidence.
