# Mobile Game Development

Use this skill when the user is building, testing, publishing, or operating mobile games on iOS, Android, tablets, foldables, or cross-platform mobile runtimes.

## Workflow

1. Identify platform targets: iOS, Android, tablets, foldables, low-end devices, app stores, regions, engine/runtime, and monetization model.
2. Define the mobile play experience: touch controls, gestures, haptics, screen orientation, safe areas, sessions, onboarding, accessibility, and offline behavior.
3. Plan technical constraints: performance budget, battery, thermals, memory, storage, network resilience, device fragmentation, crash handling, and telemetry.
4. Prepare monetization and compliance: IAP, subscriptions, ads, rewarded ads, privacy labels, consent, age ratings, child safety, and platform policies.
5. Build release readiness: signing, store metadata, screenshots, review notes, phased rollout, live ops, analytics, support, and rollback plan.

## Coverage

- Touch-first controls, gestures, haptics, orientation, safe areas, responsive UI, notches, foldables, and tablet layouts.
- Unity, Unreal, Godot, .NET MAUI-adjacent mobile shells, native iOS/Android, web-to-mobile wrappers, and cross-platform game runtimes.
- Mobile performance: FPS targets, memory, draw calls, asset size, loading, battery drain, thermal throttling, crash reports, ANRs, and startup time.
- Monetization: in-app purchases, subscriptions, ads, rewarded ads, promo codes, regional pricing, entitlement restore, and purchase validation.
- Store readiness: Apple App Store, Google Play, alternative Android stores, privacy manifests, data safety, age ratings, screenshots, trailers, and review notes.
- Live ops: events, remote config, A/B tests, seasons, leaderboards, push notifications, customer support, moderation, telemetry, and incident response.
- QA: device matrix, OS versions, screen sizes, network states, offline mode, install/update flows, save migration, localization, accessibility, and regression smoke tests.

## Guardrails

- Do not publish builds, submit store listings, enable ads/IAP, change pricing, or push live config without explicit approval.
- Flag child-directed content, gambling-like mechanics, loot boxes, privacy/consent, data collection, chat/moderation, and regional legal risk.
- Avoid excessive battery drain, manipulative monetization, inaccessible controls, and dark-pattern onboarding.
- Preserve store submission evidence, signing identity, release notes, crash data, analytics assumptions, and review correspondence.

## Output

Produce mobile game design slices, touch-control specs, device QA matrices, performance budgets, monetization checklists, store-readiness packs, live-ops plans, release gates, and approval requests.
