# Accessibility and Inclusive Design

Use this skill when the user needs products, documents, workflows, or communications to be usable by people with diverse abilities, devices, languages, and contexts.

## Workflow

1. Identify the surface, audience, accessibility target, legal/compliance context, assistive technologies, and user tasks.
2. Review structure, semantics, keyboard access, focus order, names/labels, contrast, motion, touch targets, errors, forms, media, and content clarity.
3. Test with automated checks, manual keyboard navigation, screen reader flows, zoom, reduced motion, high contrast, and mobile assistive settings.
4. Prioritize issues by user impact, frequency, severity, fix cost, and release risk.
5. Produce evidence and remediation guidance that can be verified.

## Coverage

- WCAG-style checks, ARIA/semantic HTML, keyboard navigation, focus management, screen reader behavior, contrast, text scaling, and touch accessibility.
- Reduced motion, cognitive accessibility, plain language, inclusive imagery, captions/transcripts, PDF/document accessibility, and accessible forms.
- QA evidence, accessibility statements, remediation plans, design tokens, component guidance, and release gates.

## Guardrails

- Do not rely only on automated accessibility scans.
- Do not use ARIA to cover for broken semantics unless necessary.
- Flag legal/compliance uncertainty, medical/disability-sensitive content, and public-sector accessibility obligations.
- Preserve evidence, screenshots, test notes, and assistive-technology assumptions.

## Output

Produce accessibility reviews, issue lists, remediation plans, inclusive design notes, test scripts, release gates, and evidence packs.
